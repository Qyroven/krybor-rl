# Start learning here

This is the operational entry point for Krybor RL. The repository already
contains reference implementations for Chapters 2–4; your job is to reconstruct
the reasoning behind them until you could write and debug them yourself.

## First pass: Chapters 1–4

Work in this order:

1. [Chapter 1 — Foundations](labs/ch01_foundations/README.md)
2. [Chapter 2 — Multi-armed bandits](labs/ch02_bandits/README.md)
3. [Chapter 3 — Finite MDPs](labs/ch03_finite_mdp/README.md)
4. [Chapter 4 — Dynamic programming](labs/ch04_dynamic_programming/README.md)

Do not skip Chapter 1. It does not need a large algorithm folder, but it defines
the language used to judge every later implementation: state, action, reward,
return, policy, value, agent, environment, and objective.

## One daily session

Keep a session small enough to finish:

```text
question -> prediction -> implementation -> test -> experiment -> reflection
```

Copy [journal/TEMPLATE.md](journal/TEMPLATE.md) into a dated journal entry. A
good daily commit changes one idea and leaves the repository green with
`make check`.

## Rules of evidence

- A plot without a prediction is observation, not an experiment.
- Code that runs once is not yet trusted; encode its invariant in a test.
- A seeded result is reproducible, not necessarily general; compare multiple runs.
- A rollout generated by a DP policy is not Monte Carlo learning unless sampled
  returns update an estimate or policy.
- Existing code is scaffolding. Mastery is demonstrated by explanation,
  modification, and diagnosis.

See [the definition of done](docs/DEFINITION_OF_DONE.md) before marking a topic
complete.
